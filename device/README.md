# 계속 새로 쓰는 장치

이 장치는 활동 기록을 입력하면 같은 Python 프로그램을 다시 실행하여
후보 기록과 통계 결과를 다시 생성하는 간단한 자동화 장치입니다.

## 목적

BR-A 사이트의 기록을 한 번 작성하고 끝내지 않고,
새로운 활동 기록이 생길 때마다 다시 계산하고 업데이트할 수 있도록 만들었습니다.

AI가 내용을 자동으로 사이트에 게시하지 않습니다.
생성된 후보를 직접 확인한 뒤 사이트에 반영할 내용을 선택합니다.

## 구조

    device/
    ├── README.md
    ├── input/
    │   └── records.json
    ├── output/
    │   ├── candidates.json
    │   └── stats.json
    └── src/
        ├── generate.py
        └── stats.py

## 입력 데이터

`input/records.json`에 활동 기록을 추가합니다.

각 기록은 다음 정보를 사용합니다.

- date: 기록 날짜
- type: 기록 종류
- category: BR-A에서 사용하는 능력 분류
- text: 대표 기록 내용
- source: 원자료 출처

현재 입력 데이터는 2026-08-11부터 2026-10-06까지의
실제 리추얼 기록 35건입니다.

현재 분류하는 능력은 다음 세 가지입니다.

- 자기조절력
- 대인관계력
- 자기동기력

예시:

    {
      "date": "2026-10-06",
      "type": "ritual",
      "category": "자기동기력",
      "text": "쉬는 날에도 개인 프로젝트를 보완하고 오류를 찾아보며 작업을 이어갔다.",
      "source": "리추얼 기록"
    }

## 후보 생성

`generate.py`는 입력 기록을 읽어서
사이트에 반영할 수 있는 후보 기록을 생성합니다.

    input/records.json
            ↓
        generate.py
            ↓
    output/candidates.json

후보 기록에는 다음 정보가 포함됩니다.

- 기록 날짜
- 능력 분류
- 기록 내용
- 기록 종류

후보 기록은 능력 분류와 날짜를 기준으로 정렬됩니다.

현재 입력 데이터 기준으로 35개의 후보 기록이 생성됩니다.

## 통계 계산

`stats.py`는 입력 기록을 다시 집계하여 통계 결과를 생성합니다.

    input/records.json
            ↓
        stats.py
            ↓
    output/stats.json

현재 계산하는 항목은 다음과 같습니다.

- 기록 기간
- 기록한 날짜 수
- 전체 기록 수
- 리추얼 기록 수
- 프로젝트 기록 수
- 확인된 능력 수
- 능력별 기록 수

현재 실제 결과는 다음과 같습니다.

- 기록 기간: 2026-08-11 ~ 2026-10-06
- 기록한 날짜: 35일
- 전체 기록: 35건
- 리추얼 기록: 35건
- 프로젝트 기록: 0건
- 확인된 능력: 3가지
- 자기조절력: 14건
- 대인관계력: 13건
- 자기동기력: 8건

## 실행 방법

프로젝트 루트에서 다음 명령을 실행합니다.

    python3 device/src/generate.py
    python3 device/src/stats.py

실행이 끝나면 다음 결과 파일이 생성됩니다.

- `device/output/candidates.json`
- `device/output/stats.json`

## 재현 테스트

현재 입력된 `records.json`을 기준으로 다음 결과를 확인했습니다.

    python3 device/src/generate.py

    입력 기록: 35개
    후보 기록: 35개

그리고 통계 계산 결과는 다음과 같습니다.

    전체 기록: 35개
    리추얼 기록: 35개
    프로젝트 기록: 0개
    자기조절력: 14개
    대인관계력: 13개
    자기동기력: 8개

동일한 `records.json`을 사용하고 동일한 Python 프로그램을
다시 실행하면 같은 결과를 생성할 수 있습니다.

## 새 폴더에서 재현하는 방법

프로젝트의 `br-a` 폴더를 새 위치에 복사한 뒤
새 폴더에서 다음 명령을 실행합니다.

    cd br-a
    python3 device/src/generate.py
    python3 device/src/stats.py

생성된 다음 파일을 기존 결과와 비교합니다.

    device/output/candidates.json
    device/output/stats.json

동일한 입력 파일과 동일한 Python 코드를 사용하면
같은 결과가 생성됩니다.

## 업데이트 방법

새로운 활동 기록이 생기면 `input/records.json`에 기록을 추가합니다.

그 다음 다음 명령을 다시 실행합니다.

    python3 device/src/generate.py
    python3 device/src/stats.py

생성된 결과를 확인한 뒤 사이트에 반영할 내용을 직접 선택합니다.

## 판단 방식

이 장치는 생성된 후보를 자동으로 사이트에 게시하지 않습니다.

전체 과정은 다음과 같습니다.

    새로운 기록 추가
          ↓
    Python으로 후보 생성
          ↓
    Python으로 통계 재계산
          ↓
    생성된 결과 확인
          ↓
    사람이 필요한 내용 직접 선택
          ↓
    사이트에 반영

따라서 어떤 내용을 사이트에 공개할 것인지에 대한 최종 판단은 사람이 합니다.

## 재현성

이 장치는 별도의 AI 모델이나 랜덤 요소를 사용하지 않습니다.

`records.json`의 입력 순서와 내용이 같고
같은 Python 코드를 사용하면 같은 결과를 다시 생성할 수 있습니다.

`generate.py`는 입력된 모든 기록을 후보 기록으로 변환하고,
능력 분류와 날짜를 기준으로 일정한 순서로 정렬합니다.

`stats.py`는 입력 기록을 다시 집계하여 통계를 생성합니다.

따라서 새로운 기록이 추가될 때마다
동일한 실행 방법으로 결과를 다시 만들 수 있습니다.

## 현재 한계

현재 Python 프로그램은 사용자의 로컬 환경에서 실행됩니다.

GitHub Pages에 배포된 사이트에서 `records.json`을 직접 수정한다고 해서
서버에서 Python이 자동으로 실행되는 구조는 아닙니다.

따라서 새로운 기록을 사이트에 반영하려면 다음 과정이 필요합니다.

    로컬 records.json 수정
          ↓
    Python 실행
          ↓
    결과 확인
          ↓
    사이트 수정
          ↓
    Git commit / push
          ↓
    GitHub Pages 반영

이 방식은 BR-A에서 요구하는
'새로운 기록을 추가하고 다시 계산할 수 있는 장치'를
단순한 구조로 구현하기 위한 것입니다.
