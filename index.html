01

무엇을 하고 싶은지 몰랐던 시기

대학에 들어갈 때는 반도체 산업의 전망이 좋다고 생각해 나노융합 관련 학과를 선택했습니다. 하지만 막상 대학에 들어오니 졸업 후 어떤 일을 하고 싶은지는 생각보다 쉽게 정해지지 않았습니다. 전공을 계속 공부하고 있었지만, 그 지식이 앞으로 어떤 일로 이어질지 선명하게 보이지 않았습니다. 그래서 한동안은 내가 무엇을 좋아하는지, 어떤 일을 오래 할 수 있을지 직접 경험하면서 찾아야 했습니다.

그 과정에서 기억에 남은 경험이 2학년 때 진행한 프로젝트였습니다. 센서에서 받은 정보를 다른 장치로 전달하고 휴대폰에서 알림을 확인하는 간단한 화재 알림 시스템을 만들었습니다. 처음에는 수업의 한 프로젝트였지만, 직접 만든 것이 실제로 연결되고 동작하는 모습을 보면서 생각이 조금 달라졌습니다. 코드를 작성하고 결과를 확인하는 과정이 재미있었고, 그때부터 소프트웨어를 더 제대로 배워 보고 싶다는 생각이 생겼습니다.

02

직접 배우면서 방향을 정했습니다

그렇다고 전공을 바로 버리지는 않았습니다. 고학년 때 반도체 공정 실습과 실험을 하면서 학교에서 배운 내용이 실제 현장에서는 어떻게 이어지는지 경험했습니다. 직접 실험하고 결과를 확인하면서 반도체라는 분야를 조금 더 현실적으로 이해할 수 있었습니다. 동시에 소프트웨어에 대한 관심도 계속 남아 있었습니다. 두 방향을 놓고 고민하다가 졸업을 앞두고 일단 내가 재미를 느꼈던 소프트웨어를 제대로 배워 보기로 했습니다.

2024년 8월, ITwill에서 백엔드 개발 공부를 시작했습니다. 2025년 5월까지 웹 서비스를 만드는 팀 프로젝트를 진행하면서 혼자 코드를 작성하는 것과 여러 사람이 만든 코드를 하나의 서비스로 연결하는 것은 전혀 다른 문제라는 것을 알게 됐습니다. 문제가 생기면 먼저 직접 찾아보고, 해결되지 않으면 질문하고, 다른 사람의 방법이 더 낫다면 제 방식을 바꾸기도 했습니다. 개발 지식뿐 아니라 함께 작업할 때는 내가 잘하는 것만큼 다른 사람의 작업 방식도 이해해야 한다는 것을 배웠습니다.

03

지금은 끝까지 확인하면서 만듭니다

2026년 8월, SKT ALEPH 1기를 시작하면서 여러 프로젝트와 과제를 이어 가고 있습니다. 예전에는 문제가 생기면 그 문제부터 해결하려고 했다면, 지금은 작업을 시작하기 전에 먼저 현재 상태를 확인합니다. 해야 할 일을 작은 단위로 나누고, 여러 작업이 겹치면 우선순위를 정합니다. 작업이 끝났다고 생각해도 제출하기 전에 직접 실행해 보고, 예상과 다른 부분이 있으면 다시 확인합니다. 이런 과정을 반복하면서 단순히 시작하는 것보다 끝까지 확인하고 마무리하는 것이 중요하다는 것을 배웠습니다.

2026년 10월, 과제 10의 타이핑 연구 데이터를 직접 분석했습니다. 시각적 효과가 있을 때 타이핑 성능이 떨어질 것이라고 예상하고 실험을 진행했지만, 데이터를 분석해 보니 예상했던 방향과 결과가 완전히 같지는 않았습니다. 처음 세운 가설에 맞춰 결과를 해석하지 않고 실제 데이터를 기준으로 논문을 정리했습니다. 내가 예상한 답을 증명하는 것보다 직접 확인한 결과를 받아들이는 것이 더 중요하다는 것을 배운 경험이었습니다.

개인적으로는 Maple Growth Tracker도 만들어 배포했습니다. 관심 있던 게임 데이터를 공개 API에서 가져와 필요한 정보를 가공하고, 성장 추이를 확인할 수 있도록 웹서비스로 만들었습니다. 단순히 공부한 기술을 연습하는 데서 끝내지 않고 내가 필요해서 시작한 것을 실제로 사용할 수 있는 형태까지 만들어 보면서 작은 아이디어도 직접 결과로 만들어 보는 경험을 쌓았습니다.

팀 캡스톤 프로젝트 SENTRA에서는 사내망 다계층 접근통제 시스템을 개발했습니다. 저는 Flask 백엔드 API와 로그인 인증, SQLite 데이터베이스 설계 및 마이페이지 연동을 담당했습니다. 부서와 개인별 접근 정책을 구분하고, 요청에 대한 허용·거부 결과가 감사 로그로 이어지는 구조를 팀원들과 함께 구체화하며 실제 조직에서 사용할 접근통제 흐름을 고민했습니다.

My Profile 프로젝트에서는 공개 프로필을 구성하고, 별도 기능인 Task 8에서 WebAuthn 기반 Passkey Private Space를 구현했습니다. Challenge와 RP ID·Origin 검증, 세션 기반 계정별 데이터 분리, Passkey 관리 기능을 적용하고 Render와 Supabase 환경에서 동작을 확인했습니다. 학습·시연용 프로젝트로, 실제 민감정보를 보관하는 서비스는 아닙니다.

04

앞으로 이어가고 싶은 방향

돌아보면 처음부터 개발자를 목표로 정해 놓고 온 길은 아니었습니다. 여러 경험을 직접 해보면서 내가 어떤 방식으로 일하는 사람인지 조금씩 알게 됐습니다. 지금은 모르는 것이 생기면 먼저 찾아보고, 혼자 해결하기 어려우면 질문하고, 예상과 다른 결과가 나오면 다시 확인합니다. 무엇보다 시작한 일을 중간에 멈추기보다 지금 필요한 일을 하나씩 정리하면서 끝까지 결과를 만들어 내려고 합니다. 앞으로도 새로운 일을 맡았을 때 처음부터 모든 답을 알고 있기보다 필요한 것을 찾아 배우고, 사람들과 함께 맞춰 가면서 실제로 사용할 수 있는 결과까지 만들어 내는 사람으로 일하고 싶습니다. 소프트웨어를 중심으로 경험을 쌓아 가면서, 제가 공부해 온 반도체 분야와 연결되는 소프트웨어 업무에도 계속 관심을 가지고 새로운 가능성을 찾아가고 있습니다.
